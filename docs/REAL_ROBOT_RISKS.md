# Real robot risks — proposals only

Not robot validated. All enable flags remain false. References below are repository paths and line numbers. No proposed drive changes were applied.

| Risk and evidence | Proposed verification or fix |
|---|---|
| Manual drive is field-centric with operator perspective (`src/main/java/frc/robot/RobotContainer.java:55`); align explicitly requests BlueAlliance (`src/main/java/frc/robot/commands/AlignToPegCommand.java:26`). Switching control may surprise the driver. | Check +field X/+field Y commands on blocks, then at low speed; retain blue-origin poses and explicitly document driver perspective transitions. |
| Operator perspective changes to 180 degrees for red, while disabled or initially unknown (`src/main/java/frc/robot/subsystems/CommandSwerveDrivetrain.java:276`). | Test both alliances and unknown alliance. Keep layout and align blue-origin; never apply a second alliance flip to vision. |
| Driver can seed field-centric heading (`src/main/java/frc/robot/RobotContainer.java:224`); Pigeon config is null (`src/main/java/frc/robot/generated/TunerConstants.java:76`). Code alone cannot establish mounting sign or absolute heading correctness. | Verify physical CCW produces positive yaw, verify boot heading and seed effects, then validate blue-field translation after seeding. Preserve seed inhibition during alignment. |
| No software slew limiter appears in the manual drive request (`src/main/java/frc/robot/RobotContainer.java:119`). Profile constraints in `src/main/java/frc/robot/align/AlignController.java:14` limit setpoints; feedback plus feedforward and final clamps do not guarantee bounded output acceleration. | Measure acceleration/current/traction. Consider a shared vector acceleration limiter with an explicit immediate-stop bypass, after bench validation. Sim physical acceleration is hypothetical 3 m/s² and 10 rad/s². |
| Manual deadbands are 1.084 m/s and approximately 0.471 rad/s (`src/main/java/frc/robot/RobotContainer.java:57`), larger than some/all align outputs. Align has a separate request without those deadbands (`src/main/java/frc/robot/commands/AlignToPegCommand.java:25`). | Keep the requests independent; regression-test that a future shared request cannot swallow fine correction. Check actual module friction at small outputs. |
| Default drive owns the drivetrain (`src/main/java/frc/robot/RobotContainer.java:117`); align adds that requirement (`src/main/java/frc/robot/commands/AlignToPegCommand.java:40`). Default resumes after release, and a nonzero joystick may move immediately after align's explicit zero. | Verify scheduler interruption and release at low speed. Consider driver handoff policy if this transition is undesirable. |
| Manual angular rate converts rotations/s to radians/s (`src/main/java/frc/robot/RobotContainer.java:53`); tag translations and alignment use meters/radians. Vision FPGA seconds are converted by drivetrain (`src/main/java/frc/robot/subsystems/CommandSwerveDrivetrain.java:334`). | Check measured tag centers/orientations and camera extrinsics; avoid degree/radian mistakes and timestamp double conversion. |
| Theoretical speed is 10.84 m/s (`src/main/java/frc/robot/generated/TunerConstants.java:84`), versus align's 1 m/s per axis and pi rad/s (`src/main/java/frc/robot/Constants.java:129`). Diagonal align translation can reach sqrt(2) m/s; per-axis caps are not a vector cap. | Measure actual speed scale, wheel radius/gearing, and stopping distance; consider a norm cap after tuning. Do not assume the generated theoretical speed is measured performance. |
| MegaTag2 orientation comes from fused pose and chassis yaw rate (`src/main/java/frc/robot/vision/VisionSubsystem.java:46`, `:54`); vision theta standard deviation is effectively infinite (`src/main/java/frc/robot/Constants.java:100`). Bad gyro heading may therefore corrupt vision translation without vision correcting heading. | Validate gyro heading, camera extrinsics, spin rejection and blue frame independently; log raw/accepted poses. Consider bounded pose-innovation rejection before enabling fusion. |
| All known-layout frames may fuse, including non-pegs (`src/main/java/frc/robot/vision/VisionSubsystem.java:61`). Correct IDs do not guarantee correct pose; no innovation/jump rejection exists. | Measure every layout pose and validate Limelight map consistency; add and tune an innovation gate if field data supports it. Sim pose-jump recovery is not proof against sustained estimator corruption. |
| Freshness grace is 0.5 s (`src/main/java/frc/robot/Constants.java:140`): motion may continue during this grace, then zero is commanded on the first expired update. Physical stopping takes longer. | Measure capture/delivery age and braking distance; reduce grace/caps if necessary. Test disappearance at close range with an e-stop operator. |

There is no elevator subsystem in this repository. High/unhomed scales in the test are hypothetical post-controller translation caps only; they are not a production interlock.

The headless test runs the actual profiled PID/state logic at 50 Hz with a seeded noise/dropout camera model, 60 ms latency and a 100-degree horizontal FOV. Odometry propagation/latency compensation is idealized and is not CTRE estimator simulation. It omits wheel slip, module dynamics, collisions, camera mounting occlusion, sustained pose bias, and network/scheduler jitter. The empty deployment layout must remain empty until measurements exist.
